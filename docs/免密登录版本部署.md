# WeKnora 免密登录演示版镜像离线部署

本文档对应 WeKnora 的邮箱免密登录演示版，目标平台为 `linux/amd64`。完整离线包中的基础镜像标签为 `passwordless-0.8.0-20260922`；前端登录遮罩和账号切换修复以 `passwordless-0.8.0-20260923` 前端补丁形式提供。完整离线包包含以下六个镜像：

- `weknora-local/weknora-app:passwordless-0.8.0-20260922`
- `weknora-local/weknora-ui:passwordless-0.8.0-20260922`
- `paradedb/paradedb:v0.22.2-pg17`
- `redis:7.0-alpine`
- `wechatopenai/weknora-docreader:latest`
- `neo4j:2025.10.1`

后端镜像实现邮箱免密登录、首次登录自动创建用户及个人空间；前端镜像支持通过 URL 自动登录并跳转到知识库列表。PostgreSQL、Redis、DocReader 和可选的 Neo4j 均已包含在镜像包内，服务器导入后不需要访问镜像仓库。

这里的“离线”指服务器不需要访问 Docker Hub 等镜像仓库。应用仍需能够访问你在 `.env` 中配置的 LLM、Embedding 及其他外部 API。

此包不包含默认未启用的 Sandbox、SearXNG、MinIO、Qdrant、Milvus、Weaviate、Doris、Dex 和 Langfuse 等 profile 镜像。如果后续启用这些可选功能，需要另行导入对应镜像。

## 1. 服务器要求

- Linux x86_64 / AMD64
- 推荐 Docker Engine 24 或更高版本、Docker Compose v2
- Docker Engine 19.03 与 `docker-compose` 1.24.0 可使用包内的 `docker-compose.legacy-1.24.yml`
- 建议至少 4 核 CPU、8 GB 内存、30 GB 可用磁盘
- 默认需要开放前端端口 `80`；后端 `8080` 可仅供本机或内网访问

先确认服务器架构：

```bash
uname -m
```

输出应为 `x86_64`。如果服务器输出 `aarch64` 或 `arm64`，不能使用这份 AMD64 离线镜像包。

## 2. 上传并解压部署配置

把以下文件上传到服务器同一目录：

```text
weknora-passwordless-full-images-linux-amd64.tar.gz
weknora-passwordless-deploy-config.tar.gz
SHA256SUMS
```

先校验上传文件是否完整：

```bash
sha256sum -c SHA256SUMS
```

两个文件均显示 `OK` 后执行：

```bash
sudo mkdir -p /opt/weknora-passwordless
sudo tar -xzf weknora-passwordless-deploy-config.tar.gz -C /opt/weknora-passwordless
cd /opt/weknora-passwordless
```

## 3. 导入自定义镜像

```bash
gzip -dc /path/to/weknora-passwordless-full-images-linux-amd64.tar.gz | docker load
docker image inspect \
  weknora-local/weknora-app:passwordless-0.8.0-20260922 \
  weknora-local/weknora-ui:passwordless-0.8.0-20260922 \
  paradedb/paradedb:v0.22.2-pg17 \
  redis:7.0-alpine \
  wechatopenai/weknora-docreader:latest \
  neo4j:2025.10.1 \
  --format '{{.RepoTags}} {{.Os}}/{{.Architecture}}'
```

六个镜像都应显示 `linux/amd64`。

## 4. 配置环境变量

```bash
cp .env.example .env
chmod 600 .env
```

至少修改以下配置：

```dotenv
# 对外端口
FRONTEND_PORT=80
APP_PORT=8080

# 基础服务密码
DB_USER=postgres
DB_PASSWORD=请替换为随机密码
DB_NAME=WeKnora
REDIS_PASSWORD=请替换为随机密码

# 应用密钥
JWT_SECRET=请替换为随机长字符串
# 必须正好为 32 个字符，并长期保留；丢失后已加密的模型密钥无法恢复
SYSTEM_AES_KEY=请替换为32字符密钥

# 演示版免密登录
WEKNORA_AUTH_PASSWORDLESS_EMAIL_LOGIN_ENABLED=true
WEKNORA_AUTH_PASSWORDLESS_EMAIL_AUTO_REGISTER_ENABLED=true
WEKNORA_AUTH_DEFAULT_TENANT_MODE=create_personal

# 全局问答模型
LLM_MODEL_NAME=你的模型名
LLM_BASE_URL=https://你的模型接口/v1
LLM_API_KEY=你的密钥
LLM_PROVIDER=openai

# 全局 Embedding 模型
EMBEDDING_MODEL_NAME=你的模型名
EMBEDDING_BASE_URL=https://你的模型接口/v1
EMBEDDING_API_KEY=你的密钥
EMBEDDING_PROVIDER=openai
EMBEDDING_DIMENSION=模型实际输出维度
```

可以用以下命令生成安全的基础密钥：

```bash
openssl rand -hex 24   # 可用于 DB_PASSWORD / REDIS_PASSWORD
openssl rand -hex 32   # 可用于 JWT_SECRET
openssl rand -hex 16   # 输出正好 32 个字符，可用于 SYSTEM_AES_KEY
```

`EMBEDDING_DIMENSION` 必须与模型实际返回的向量长度完全一致。例如本次测试使用的 `doubao-embedding-vision` 返回 `2048` 维。

如果需要启用知识图谱和 Neo4j，再设置：

```dotenv
NEO4J_ENABLE=true
NEO4J_URI=bolt://neo4j:7687
NEO4J_USERNAME=neo4j
NEO4J_PASSWORD=请替换为随机密码
```

## 5. 启动

```bash
docker compose \
  -f docker-compose.yml \
  up -d --pull never
```

该命令启动应用、前端、PostgreSQL、Redis 和 DocReader，并自动执行数据库迁移。`pull_policy: never` 和 `--pull never` 会阻止 Docker 访问镜像仓库。

需要同时启动 Neo4j 时使用：

```bash
docker compose \
  --profile neo4j \
  -f docker-compose.yml \
  up -d --pull never
```

查看状态：

```bash
docker compose \
  -f docker-compose.yml \
  ps

docker logs --tail 100 WeKnora-app
```

### Docker 19.03 / docker-compose 1.24.0

旧版环境不要叠加前面的两个 Compose 文件，直接使用兼容文件和 seccomp 覆盖文件。默认不启动 Neo4j：

```bash
docker-compose \
  -f docker-compose.legacy-1.24.yml \
  -f docker-compose.legacy-1.24-seccomp.yml \
  up -d --no-build frontend
```

`frontend` 会自动带起 app、PostgreSQL、Redis 和 DocReader。需要 Neo4j 时，先在 `.env` 中配置 `NEO4J_ENABLE=true` 和 Neo4j 连接信息，然后执行：

```bash
docker-compose \
  -f docker-compose.legacy-1.24.yml \
  -f docker-compose.legacy-1.24-seccomp.yml \
  up -d --no-build neo4j frontend
```

查看旧版环境状态：

```bash
docker-compose \
  -f docker-compose.legacy-1.24.yml \
  -f docker-compose.legacy-1.24-seccomp.yml \
  ps
```

Docker 19.03 不支持 `host-gateway`，兼容文件已移除该映射。如果 LLM 或 Embedding 服务运行在同一台宿主机，不要使用 `host.docker.internal`，请在 `.env` 中填写宿主机实际的内网 IP。

Docker 19.03 的旧版默认 seccomp 规则会让 PostgreSQL 17 初始化时报 `postgres -V: Operation not permitted`，也可能让 DocReader 的 Tokio 执行器报 `PermissionDenied: Operation not permitted`。`docker-compose.legacy-1.24-seccomp.yml` 仅对 PostgreSQL 和 DocReader 设置 `seccomp=unconfined`，启动旧版环境时应与兼容文件一起使用。

```bash
docker-compose \
  -f docker-compose.legacy-1.24.yml \
  -f docker-compose.legacy-1.24-seccomp.yml \
  up -d --no-build --force-recreate postgres docreader
```

如果完整离线包中的前端仍是 `passwordless-0.8.0-20260922`，请导入 `passwordless-0.8.0-20260923` 前端补丁。两个分卷合并后导入：

```bash
cat weknora-ui-no-login-flash-linux-amd64.tar.gz.part01 \
    weknora-ui-no-login-flash-linux-amd64.tar.gz.part02 \
    > weknora-ui-no-login-flash-linux-amd64.tar.gz

gzip -dc weknora-ui-no-login-flash-linux-amd64.tar.gz | sudo docker load
```

确保 `docker-compose.ui-20260923.yml` 与两个兼容 Compose 文件位于同一目录，然后重建前端：

```bash
docker-compose \
  -f docker-compose.legacy-1.24.yml \
  -f docker-compose.legacy-1.24-seccomp.yml \
  -f docker-compose.ui-20260923.yml \
  up -d --no-deps --no-build --force-recreate frontend
```

也可以直接把 `docker-compose.legacy-1.24.yml` 中 `frontend.image` 改为：

```yaml
image: weknora-local/weknora-ui:passwordless-0.8.0-20260923
```

导入镜像不会自动替换正在运行的容器，必须执行上面的 `--force-recreate frontend`。

应用健康检查：

```bash
curl -f http://127.0.0.1:8080/health
```

启动日志中应出现：

```text
[builtin-models] applied: 2 upserted, 0 pruned
```

## 6. 验证免密跳转

访问以下地址，把域名和邮箱替换成实际值：

```text
http://你的域名/login?demo_email=user%40example.com&redirect=%2Fplatform%2Fknowledge-bases
```

邮箱必须经过 URL 编码，例如 `user@example.com` 编码为 `user%40example.com`。未注册的邮箱会自动创建用户和个人空间，然后进入：

```text
/platform/knowledge-bases
```

如果当前浏览器已经登录账号 A，再打开带账号 B 邮箱的链接，系统会在 B 登录成功后清理 A 的本地令牌和账号缓存，并切换到 B。B 登录失败时会保留 A 的现有会话。

模型管理页面：

```text
http://你的域名/platform/settings?section=models
```

## 7. 更新配置

修改 `.env` 后必须重新创建容器，普通的 `docker restart` 不会重新读取环境变量：

```bash
docker compose \
  -f docker-compose.yml \
  up -d --pull never --force-recreate app frontend
```

修改 `config/builtin_models.yaml` 后，只需重新创建 `app`：

```bash
docker compose \
  -f docker-compose.yml \
  up -d --pull never --force-recreate app
```

## 8. 停止与备份

停止服务但保留数据卷：

```bash
docker compose \
  -f docker-compose.yml \
  down
```

不要使用 `down -v`，它会删除数据库和文件数据卷。升级或迁移前至少备份 PostgreSQL 数据与 Docker 数据卷。

## 9. 使用边界

此版本只要知道邮箱就能登录对应账号，自动登录链接也可以被复制或转发。它适合受控网络中的小批量演示。对公网开放时，应在入口网关增加访问限制，或改用一次性签名票据、OIDC 等正式单点登录方式。
